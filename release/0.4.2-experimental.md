# LootGlow v0.4.2 Experimental

## Nexus file details

- **File name:** LootGlow v0.4.2 Experimental - Shader Recovery
- **File version:** 0.4.2
- **Category:** Optional files (leave v0.4.1 as the main file)
- **Summary:** Experimental shader stack recovery for all glow tiers after cell reload, with opt-in cleanup for doubled effects on older saves.

## Description

This experimental build restores glow intensity after leaving and re-entering a cell. It rebuilds the primary and accent shader stacks for Insane and Unique containers, and the stacks for Low, Medium, High, and standalone Lockpick glows. It also restores automatic glow when a container's graphics load.

The included INI enables shader recovery and leaves `LegacyGlowNormalizationMode=0`. If an existing save shows duplicated or overly bright glow after cell reload, set `LegacyGlowNormalizationMode=1` in `LootGlow.ini`. With that setting, glow still appears automatically; on the first hover after graphics load, LootGlow checks for extra matching effects and, when found, removes and rebuilds its configured stacks. The cleanup may affect another mod that applies the same configured shader to the same container.

**Compatibility:** Built for Oblivion Remastered executable 1.512.105.0 with the matching OBSE64 and Address Library setup. Shader recovery validates this executable's fingerprint and skips the recovery hooks if it does not match. Back up your save before testing this experimental file.

**Installation:** Install this archive with a mod manager or extract its `OblivionRemastered` directory into the game folder. Replace the existing `LootGlow.dll` and `LootGlow.ini` in `OblivionRemastered/Binaries/Win64/OBSE/Plugins/`. Keep a copy of a customized INI before replacing it.

**Testing so far:** The shader logic was tested in game on fresh and existing saves. Low, Medium, High, Insane, and Unique containers glowed correctly through cell re-entry; logs confirmed their expected stack counts. A Lockpick glow was visually confirmed after exit and re-entry, but the latest log did not independently capture its stack count. The v0.4.2 DLL changes version metadata only relative to that tested logic. Please report the game version, INI settings, save history, and `LootGlow.log` with any issue.
